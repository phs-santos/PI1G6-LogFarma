# Grafo de conhecimento com graphify

- **Implementado em:** 2026-11-03
- **Última alteração:** —
- **Requisitos:** —

## Em poucas palavras

O graphify desenha um **mapa do metrô** do projeto: cada arquivo, função, regra e conceito do domínio vira uma estação, e as linhas mostram quem usa quem. Em vez de o assistente de IA andar a pé por todas as ruas (abrir arquivo por arquivo), ele olha o mapa primeiro e vai direto à estação certa — mais rápido e gastando menos tokens.

## O que

- Grafo gerado a partir do monorepo inteiro: 73 arquivos, 580 nós, 759 arestas, 23 comunidades.
- Saídas em `graphify-out/` (fora do git): `graph.html` (visual interativo), `graph.json` (dados) e `GRAPH_REPORT.md` (relatório).
- Seção `## graphify` no `CLAUDE.md` da raiz: o Claude Code consulta o grafo (`graphify query`) antes de sair lendo arquivos.
- Hooks do Claude Code que lembram de usar o grafo, em `.claude/settings.local.json` (pessoal, fora do git).

## Por que

- O projeto vai crescer em três pacotes + infra; o grafo dá uma visão de conjunto (ex.: quais regras do `CLAUDE.md` ligam backend e frontend) e reduz o custo de contexto dos agentes.

## Onde

| Caminho                           | O que é                                    | No git?            |
| --------------------------------- | ------------------------------------------ | ------------------ |
| `graphify-out/`                   | Grafo, relatório, cache e manifesto        | Não (`.gitignore`) |
| `CLAUDE.md` (seção `## graphify`) | Instruções para o Claude Code usar o grafo | Sim                |
| `.claude/settings.local.json`     | Hooks `PreToolUse` do graphify             | Não (pessoal)      |

## Escolhas feitas

| Escolha                                                                                 | Alternativas consideradas                                                          | Motivo                                                                                           |
| --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `graphify-out/` fora do git                                                             | Versionar o `graph.json`                                                           | Ele é reescrito inteiro a cada build e tem caminhos absolutos da máquina; cada pessoa gera o seu |
| Hooks em `settings.local.json`                                                          | Deixar no `.claude/settings.json` do projeto (padrão do `graphify claude install`) | O hook aponta para `/Users/<voce>/.local/bin/graphify`; no computador dos colegas daria erro     |
| Hook de `post-commit` do git **não** instalado                                          | `graphify hook install` (reconstrói o grafo a cada commit)                         | Bloqueado pela política de permissões do agente; fica a critério de cada pessoa instalar         |
| Extração semântica pelo próprio Claude (sem chave Gemini)                               | Usar `GEMINI_API_KEY`                                                              | Não havia chave configurada; o graphify não exige                                                |
| `.claude/` e `AGENTS.md` duplicados entram no grafo como nós ligados por "semelhante a" | Excluir duplicatas                                                                 | Mantém fiel ao repositório; a duplicação fica visível                                            |

## Como usar

```bash
uv tool install graphifyy          # uma vez por máquina
graphify query "como o frontend usa o style-guide"
graphify path "App()" "Button()"
graphify explain "Glossário domínio → código"
graphify update .                  # depois de mudar código (só AST, sem custo de LLM)
```

No Claude Code: `/graphify .` reconstrói tudo (inclusive os docs); `/graphify . --update` só o que mudou.
Para reconstruir automaticamente a cada commit: `graphify hook install` (opcional, por pessoa).

## Observações

- `packages/style-guide/src/tokens/tokens.css` foi ignorado pelo graphify por ter "tokens" no nome (filtro de arquivos sensíveis). Não é segredo — são tokens de design.
- O diagnóstico apontou 2 arestas com ponta solta e ~75 arestas repetidas colapsadas (quase todas chaves repetidas de YAML nos workflows/templates). O grafo é utilizável.
- Custo do primeiro build: ~161 mil tokens de entrada (extração dos 32 documentos).
