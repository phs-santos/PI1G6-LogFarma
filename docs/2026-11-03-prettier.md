# Formatação automática com Prettier (indentação de 4)

## Em poucas palavras

O Prettier é o **corretor ortográfico da arrumação do código**: ninguém precisa discutir se é 2 ou 4 espaços, aspas simples ou duplas — ele arruma tudo do mesmo jeito, sempre. Agora o projeto inteiro usa **4 espaços** de indentação, e o editor arruma sozinho ao salvar.

## O que

- `prettier` instalado como dependência de desenvolvimento na raiz do monorepo.
- `.prettierrc.json` com as regras; `.prettierignore` para pular arquivos gerados.
- `.editorconfig` atualizado para 4 espaços (editores sem Prettier também seguem).
- Scripts `pnpm format` (formata) e `pnpm format:check` (só confere).
- `.vscode/settings.json` (formatar ao salvar) e `.vscode/extensions.json` (recomenda Prettier e EditorConfig).
- O repositório inteiro foi formatado uma vez (45 arquivos).
- `CLAUDE.md`/`AGENTS.md`: regra de rodar `pnpm format` antes de terminar uma tarefa.

## Por que

- Pedido do grupo: padronizar a indentação em 4.
- Evita diffs de PR cheios de mudança de espaço e discussões de estilo.

## Escolhas feitas

| Escolha                          | Alternativas consideradas       | Motivo                                                                                                       |
| -------------------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Prettier                         | Biome, dprint                   | Padrão de mercado, suporta TS/TSX/CSS/HTML/JSON/MD/YAML e integra com qualquer editor                        |
| 4 **espaços** (`useTabs: false`) | Tabs de largura 4               | Aparece igual no GitHub, no terminal e em qualquer editor. Para usar tab de verdade, basta `"useTabs": true` |
| YAML com 2 espaços               | 4 em tudo                       | Convenção de GitHub Actions e Docker Compose; os exemplos da documentação deles usam 2                       |
| `printWidth: 100`                | 80 (padrão)                     | Com 4 espaços, 80 colunas quebraria linhas demais                                                            |
| Aspas duplas, `;`, vírgula final | Outras combinações              | Já era o estilo do código; só a indentação mudou                                                             |
| Formatar também Markdown         | Ignorar `.md`                   | Mantém tudo consistente; o único efeito foi alinhar as tabelas                                               |
| Sem checagem no CI por enquanto  | `pnpm format:check` no `ci.yml` | Mexer em `.github/workflows/` precisa de aprovação (regra dos agentes)                                       |

## Como usar

```bash
pnpm format         # arruma tudo
pnpm format:check   # confere (útil antes do PR)
```

No VS Code: instale a extensão recomendada (aparece um aviso ao abrir o projeto) e o arquivo é formatado ao salvar.
